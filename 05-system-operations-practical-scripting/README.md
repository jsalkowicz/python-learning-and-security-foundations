## Importing the `os` module

The `os` module is built into Python, so I can import it without installing another package:

```python
import os
```

It provides functions for interacting with the operating system and filesystem.

## Current working directory with `os.getcwd()`

I used:

```python
print(os.getcwd())
```

to display Python's current working directory.

This helped connect the file-handling work from the previous section to the idea of a working directory. Relative paths are interpreted from the directory Python is currently working in.

## Listing directory contents with `os.listdir()`

I used:

```python
print(os.listdir())
```

to return the contents of the current working directory.

The result was a Python list containing file and folder names.

I then combined `os.listdir()` with a `for` loop:

```python
for i in os.listdir():
    print(i)
```

This printed each item on its own line and connected the `os` module back to the loop concepts I practiced earlier.

## Changing the working directory with `os.chdir()`

I practiced changing Python's working directory with:

```python
os.chdir(r"C:\Users\example\Desktop")
print(os.getcwd())
```

The public example uses an anonymized Windows path.

One thing I learned is that `os.chdir()` changes the working directory for the running Python process. It does not permanently change the PowerShell terminal's current directory after the script exits.

I also saw that:

```python
print(os.chdir(...))
```

prints:

```text
None
```

because `os.chdir()` performs an action but does not return a useful value.

## Creating a directory with `os.mkdir()`

I created a folder with:

```python
print(os.mkdir("testfolder"))
```

The folder was created in the current working directory.

`os.mkdir()` also returned `None`, which reinforced the difference between a function that performs an action and a function that returns a value.

I verified the folder existed with PowerShell's `ls` command.

If the same folder already exists, trying to create it again can raise a `FileExistsError`.

## Removing an empty directory with `os.rmdir()`

I removed the folder with:

```python
print(os.rmdir("testfolder"))
```

I then used `ls` again to verify that the folder was gone.

`os.rmdir()` removes an **empty** directory. If the directory contains files or other folders, Python will not remove it with this function.

Like `os.chdir()` and `os.mkdir()`, it returned `None` after successfully performing the action.

## Troubleshooting note

At the beginning of this section, I ran `hello.py` and did not see the expected output.

The file had unsaved changes in the editor, so Python ran the previously saved version of the script. After saving the file and running it again, `os.getcwd()` produced the expected output.

This was a useful reminder that the terminal runs the saved version of a Python file, not unsaved changes that are only visible in the editor.

## What I did not understand right away

- `os.getcwd()` returns the current working directory.
- `os.listdir()` returns a list of directory contents.
- A `for` loop can process each item returned by `os.listdir()`.
- `os.chdir()` changes Python's working directory but does not permanently move the PowerShell terminal.
- Functions such as `os.chdir()`, `os.mkdir()`, and `os.rmdir()` can successfully perform an action while returning `None`.
- `os.mkdir()` creates a directory relative to the current working directory unless a different path is provided.
- `os.rmdir()` only removes an empty directory.
- Running a Python script before saving the latest changes can make it look like the new code did not run.

## Why this matters for security and AI security

Filesystem and operating-system operations are useful building blocks for automation.

Security scripts often need to:

- identify the current working location
- enumerate files in a directory
- process many log, JSON, or evidence files
- create folders for output or reports
- organize generated security artifacts
- move between working locations safely

These same basics can later support AI-security workflows that process evaluation results, model logs, telemetry, test artifacts, and other files generated by security tooling.
